# Аудит Memory Wiki — открытая сводка

Полный эксплуатационный отчёт сохранён **только локально** в защищённой копии у владельца. Здесь намеренно нет идентификаторов чатов, точных путей резервных копий, PID, конфигураций профилей, размеров пользовательской памяти или содержимого записей.

## Область

Проверяется внешний плагин Memory Wiki: границы доступа к claims и документам, FTS/Qdrant, журнал и восстановление, работа с несколькими профилями. Тесты используют синтетические записи и изолированный `HERMES_HOME`; это не доказательство отсутствия любых дефектов.

## Промежуточные результаты

- Последний полный изолированный прогон на Windows: **797 тестов прошли, 2 пропущены**. История file ID ограничена безопасным для checkpoint размером: попытка превышения отклоняется транзакционно, а сохранение допустимого объёма проверено реальным checkpoint. Ранее прошли **126 связанных тестов**. Первый GitHub Actions прогон выявил, что тест Windows-алиаса ошибочно выполнялся на Linux; добавлен платформенный маркер, и новый точный SHA должен пройти всю матрицу.
- Для текущих активных claims в проверенных профилях совпали множества ID SQLite/FTS и активных Qdrant-целей. Паритет ID не доказывает эквивалентность форматов FTS или полноту документного embedding.
- FTS v3 и старые профильные копии v2 несовместимы по формату. Ручное изменение маркера без согласованного обновления кода и миграции запрещено.
- Документные фрагменты с отсутствующей ссылкой и со ссылкой на архивный claim не переиндексируются массово: доступ к проекту и намерение архивирования требуют отдельной проверки.

## Проверка pre-push находок

Первоначальные блокеры и продолжения их классов воспроизведены на синтетических данных (RED→GREEN): очистка topic в FTS и Qdrant, отсутствие записи при федеративном поиске, защита старого FTS-профиля от совпадения по скрытому секрету, сохранение privacy-delete при гонках с upsert, проверка владельца connector и Windows-алиасов до чтения файла, единый guard перед reranker и во всех модельных документных полях. Документные выборки предпочитают безопасный результат, не передавая отвергнутый текст reranker. Поздний независимый review выявил дополнительный Windows-обход через исчезнувший либо заменённый путь индексированного файла с сохранившимся hardlink; он воспроизведён на синтетических данных. Добавлена история идентификаторов открытого файла и атомарная проверка владельца физического объекта, а также проверка scan до ограниченного отбора кандидатов. Целевые документные и checkpoint-тесты прошли. Идентификатор *старого* файла, заменённого ещё до введения журнала идентичности, восстановить нельзя: этот исторический случай не имеет строгой гарантии без отдельной операторской аттестации или консервативной блокировки. Повторные тесты recovery и последний полный изолированный suite прошли. Независимое review обнаружило риск обрезания длинной истории file ID в checkpoint; запись теперь ограничена до безопасного размера и проверена синтетическими тестами. Результат CI проверяется по точному SHA в GitHub Actions; **развёртывание остаётся на паузе до успешной матрицы**.

Подписанный `hermes_trust_core` в данной установке отсутствует. Временный локальный guard не означает строгую защиту от всех prompt-инъекций; включать strict-режим без проверенного ядра нельзя. Проверка живых процессов после развёртывания ещё не выполнена; статус CI следует сверять с точным SHA в GitHub Actions.

## Условия выпуска и развёртывания

1. Исправить перечисленные дефекты на вымышленных данных, сохранить границы ACL и модельного вывода, прогнать полный suite и lint; проверить независимым review.
2. Опубликовать проверенный commit и подтвердить точный SHA на GitHub вместе с CI этого SHA; не переносить локальные приватные артефакты в публичный репозиторий.
3. Перед обновлением каждого именованного профиля получить отдельный подтверждённый владельцем снимок SQLite+journal и сохранить старый код для отката. Qdrant-векторы не входят в такие снимки.
4. Развернуть **полный** согласованный комплект модулей и metadata, не копировать конфигурации/секреты между профилями; после контролируемого внешнего перезапуска проверить свежий импорт, FTS v3, пустые legacy-поля, Qdrant-паритет, предзагрузку памяти и реальные ответы ботов.
5. Не запускать общий reindex или автоматическое восстановление архивных claims без доказанного дефицита и проверки прав.
